## Этап 2 — Домен (Core) · 2026-11-09

**Сделано:**
- Модели: `TimeRange` (value object, минуты от начала даты), `WorkEntry`, `EntryDraft`, `Period`/`PeriodKind`, `AppSettings`, `ThemePreference`, `WindowPlacement`.

- `PeriodNavigator` (периоды, ◀/▶, предыдущий период, учитываемый конец), `StatisticsCalculator` + `PeriodStatistics` (все показатели F3.2, ряды для графиков по дням/месяцам/дням недели), `CsvExporter` (F3.5), `RuFormat` (русские даты и подписи периодов).
- Интерфейсы `IEntryRepository`, `ISettingsStore` и `EntryService` — сценарии добавления (текст/форма), редактирования, удаления и отмены поверх них.
- Документы `docs/INPUT_FORMAT.md`, `docs/STATISTICS.md`, ADR-0003, ADR-0007.

**Решения:**
- `RuFormat` задаёт названия месяцев и дней недели явно поверх `CultureInfo("ru-RU")`: на Windows с NLS и ICU, macOS и Linux сокращения различаются («нояб.» / «ноя»), а вывод и тесты должны быть одинаковыми.
- «Похоже на второй интервал» — 3–4 цифры, `H:mm` или «1–2 цифры + ещё время» в начале комментария; комментарий «3 задачи» допустим (см. INPUT_FORMAT, правило 9).
- `0900 0000` трактуется как конец в полночь (`end_min = 1440`), так форма с `TimePicker` (где нет «24:00») тоже может ввести такую запись.
- Сравнение с предыдущим периодом — с предыдущим периодом **целиком** (STATISTICS.md).
- Среднее по дням недели — по календарным дням (дни без записей в знаменателе).

**Проблемы и как решены:**
- Падение статического конструктора `RuFormat`: `Capitalize` обращался к ещё не созданной `Culture` → переход на `char.ToUpperInvariant`. Нашёлся тестами статистики.
- Две ошибки в ожиданиях собственных тестов (интервал «до» на самом деле был внутри; длина произвольного периода) — исправлены тесты, не код.

**Проверка:** `dotnet test` Core — 231 passed, 0 failed (парсер: 38 корректных + 33 ошибочных кейса из таблицы F1.4 и пограничных, плюс отдельные проверки); покрытие строк Core — 92,8%.

**Сделано:**

- Полноценный `--self-test`: 14 проверок на тех же DI-регистрациях, что и UI (миграции, нативный SQLite, добавление, чтение, редактирование, пересечение, ночная смена, мягкое удаление и восстановление, статистика, поиск по кириллице, CSV, настройки, бэкап, русские форматы). Отдельная БД в `self-test-db`, пользовательская `worktime.db` не трогается.
- `docs/DATA_MODEL.md`, ADR-0002, ADR-0004.

**Решения:**
- Автобэкап делается **до** миграций — чтобы при неудачной миграции осталась исходная БД.
- Таблица `schema_version` создаётся мигратором (`CREATE TABLE IF NOT EXISTS`), а не первой миграцией: так версия читается даже у пустого файла.
- Миграция 0002 (частичный индекс по `deleted_at`) — настоящая польза для очистки и одновременно проверка сценария «версия N → N+1».
- Повреждённые значения настроек заменяются значениями по умолчанию, а не ломают запуск.
- Self-test без `--data-dir` работает во временной папке — случайный запуск не трогает реальные данные.
- `AppSettings.LastAutoBackup` удалён: признак «бэкап сегодня уже был» — наличие файла копии за сегодня (проще и надёжнее).

**Проблемы и как решены:**
- Тест «повреждённый файл БД» подтвердил, что `factory.Open()` на мусорном файле падает с `SqliteException` ещё на `PRAGMA journal_mode`, — она оборачивается в `DatabaseOpenException`, файл остаётся байт-в-байт тем же.

**Проверка:** `dotnet test` Data — 45 passed (миграции с нуля и N→N+1, откат упавшей миграции, отказ открывать БД новее программы, CRUD, атомарность пакетного добавления, мягкое удаление/восстановление, очистка через 30 дней, бэкап и ротация 14 копий, поиск «Созвон» ↔ «созвон», 40 параллельных записей + `integrity_check`, повреждённый файл не удаляется); покрытие Data — 98,0%.

**Решения:**
- Плоский список с двумя типами строк вместо вложенных групп — так работает множественный выбор через границы дней и виртуализация `ListBox`. Заголовки дней не выделяются (`IsEnabled` через стиль с `x:DataType`).
- Поле быстрого ввода многострочное (`AcceptsReturn`), Enter перехватывается туннельным обработчиком: вставка нескольких строк работает без отдельного диалога.
- Отмена удаления доступна, пока после удаления не было других изменений (ADR-0004) — восстановление не может создать пересечение.
- Ошибка добавления (пересечение) показывается на месте предпросмотра, ввод не теряется.

**Проблемы и как решены:**
- Partial-свойства CommunityToolkit с инициализаторами несовместимы со сгенерированным кодом → значения задаются в конструкторах.
- Сеттеры в конструкторах ViewModel вызывали загрузку из ещё не подготовленной БД → флаг `_active` (до первой явной `LoadAsync` к БД не обращаемся).
- В лямбде `(s, _) => _ = LoadAsync()` дискард `_` оказался параметром `EventArgs` — ошибка компиляции CS0029, параметры переименованы.
- Avalonia 12: `TextBox.Watermark` устарел (`PlaceholderText`), `$parent[Window].X` не видит свойства наследника → `$parent[views:EditEntryWindow]`, `ListBox` не фокусируемый (фокус у `ListBoxItem`).
- Плоские VM-тесты падали «The calling thread cannot access this object»: `ThemeService` менял тему вне UI-потока → смена темы через `Dispatcher`, если вызов не из UI-потока.
- **Найдена гонка:** быстрые изменения настроек подряд сохранялись параллельно, и более раннее сохранение могло завершиться последним, затерев тему. `SettingsService` теперь сохраняет строго по очереди и всегда пишет самое свежее состояние.

**Проверка:** App.Tests — 49 passed (на тот момент), CI run #4 ✅.

**Фактическая структура против описанной в задании:**
- Задание называет файл `PROMPT-notepad.md` «корневым», но в корне репозитория его не было — он лежал в папке загрузок владельца. Он скопирован дословно в `docs/prompts/2026-11-10-notepad.md` (`diff` — без различий); исходный файл вне проекта не тронут (правило «ничего не трогать за пределами папки проекта»), поэтому шаг «удалить корневой файл» в этапе 8 выполнять не с чем.
- «Контрола быстрого ввода» как отдельного класса в v1.0.0 не было: поле, предпросмотр и форма были частью `JournalViewModel` / `JournalView`. Чтобы не дублировать, они вынесены в `EntryInputViewModel` + `EntryInputView`, и «Журнал» теперь сам использует этот контрол.
- Отмена была устроена внутри `JournalViewModel` и вызывалась по `Ctrl+Z` с любой вкладки. Вынесена в `UndoToastViewModel` + `UndoToastView`; у каждой вкладки свой экземпляр.

**Решения (подробно — ADR-0009):**
- Блокнот — отдельные таблицы поверх `entries`; `entries` не меняется. Добавление идёт через `EntryService` с подставленным способом сохранения (делегат `EntryInserter`): разбор, правила и проверка пересечений — общие, а вставку записей вместе с привязками делает `NotepadRepository` одной транзакцией (`BEGIN IMMEDIATE`, чтобы проверка «есть ли текущий лист» и вставка не разрывались).
- Инвариант «текущий лист — не больше одного» закреплён в БД уникальным индексом по константе с условием (`ON notepad_sheets((1)) WHERE cleared_at IS NULL AND deleted_at IS NULL`), а не только кодом. В схеме из задания этого индекса нет — он добавлен как защита инварианта, остальная схема — дословно из задания.
- Архив «живой»: записи листа читаются соединением с `entries`. Удаление в «Журнале» поэтому «само» убирает запись из блокнота и архива, а отмена возвращает — без единого изменения в таблицах блокнота.
- «Блокнот» поднимает `AppEvents.EntriesChanged` только при добавлении и правке. ✕, «Очистить всё», «Удалить из архива» событие не поднимают — они не меняют записи.
- Название листа сохраняется при уходе фокуса из поля и по `Enter` (а не на каждую букву); если вкладку закрыли, не выходя из поля, название сохраняется при снятии вкладки с экрана. Пустое название лист не создаёт.
- Пустой блокнот очистить нельзя (кнопка неактивна, сервис возвращает `null`) — в архиве не появляются пустые листы.
- Карточка архива без названия называется «Лист 3–6 нояб.» по датам записей; если записей не осталось — «Лист от 6 нояб.» по дате очистки и пометка «записи удалены».

**Проблемы и как решены:**
- **Найдена дыра в отмене «Журнала».** С появлением второй вкладки, меняющей записи, стал возможен сценарий: удалить в журнале 09:00–12:00 → добавить в блокноте 10:00–11:00 → `Ctrl+Z` в журнале возвращает первую запись поверх второй — пересечение, которого не должно быть (ADR-0007). Теперь «Журнал» сбрасывает свою отмену, когда записи изменили в другом месте; тест `ChangeInNotepad_InvalidatesJournalUndo`.
- Тесты «перезапуска» (S3, S12): `TestHost` удалял папку данных и при создании, и при освобождении, поэтому второй запуск на той же БД видел пустую базу (0 привязок вместо ожидаемых). Добавлены `keepExisting` и `KeepDataOnDispose`.
- После сдвига разделов тесты и генерация скриншотов, ходившие по номерам (`Navigate("2")` = «Статистика»), открывали не те страницы — номера обновлены, а `Main_Navigation` теперь проверяет и названия, и подсказки клавиш.
- Покрытие Core считается по лучшему отчёту одного тестового проекта, поэтому сервис блокнота покрыт в `Core.Tests` на хранилище в памяти (`InMemoryNotepadRepository`), а не только интеграционными тестами App.
