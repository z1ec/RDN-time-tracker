## 1. Проблема (сообщение от пользователя)

> В блокноте записываю `1100 1300`, удаляю (✕) и снова записываю `1100 1300` — не даёт записать, говорит, что запись уже есть. А суть в том, чтобы блокнот был как песочница: делай что хочешь. Если в базе есть пересечения за эту дату — данные в базу не записываем.

**Причина:** в v1.1.0 блокнот — это только окно на записи `entries`. Кнопка ✕ убирает строку из блокнота, но запись остаётся в базе (так задумано, F8.11), поэтому повторный ввод пересекается с ней и отклоняется (F8.3).

## 2. Новая модель (решения согласованы с пользователем)

У блокнота теперь **свои строки** с собственными датой, временем и комментарием. Строка может быть **связана** с записью в `entries` (тогда это время учтено в Журнале и Статистике) или **не связана** (тогда оно есть только в блокноте).

### Требования (новые ID — F9.x; используй их в коммитах, тестах и `docs/FEATURES.md`)

- **F9.1 Блокнот принимает любую строку, корректную по формату.** Пересечения и дубликаты внутри блокнота разрешены. Ошибки остаются только у парсера: неверный формат, несуществующая дата, дата в будущем и т.п. Многострочная вставка по-прежнему атомарна **по ошибкам формата**: одна невалидная строка — не добавляется ничего.

- **F9.2 Запись в базу только без пересечений.** При добавлении строка проверяется на пересечения со всеми записями базы, тем же валидатором, что и раньше, с учётом ночных смен на соседних днях.
  - Пересечений нет — создаётся обычная запись в `entries`, и строка связывается с ней. Строка и запись создаются в **одной транзакции**.
  - Пересечение есть — строка добавляется **только в блокнот**, в базу ничего не пишется.
  - При многострочной вставке строки обрабатываются по порядку в одной транзакции. Строка, которая пересекается с записью, созданной из предыдущей строки той же вставки, тоже становится «не в статистике».

- **F9.3 Статусы строки** (вычисляются, отдельно не хранятся):

  | Статус | Условие | Как выглядит |
  |---|---|---|
  | **в статистике** | связана, и время/дата/комментарий совпадают с записью | обычная строка |
  | **не в статистике** | не связана | приглушённая строка, метка «не в статистике»; подсказка «Пересекается с записью 11.11 11:00–13:00 «…» — в статистику не записано» (конфликт ищется на момент показа; если его уже нет — «В статистику не записано: при добавлении было пересечение») |
  | **в статистике другое время** | связана, но значения отличаются от записи (см. F9.5) | метка «в статистике: 09:00–19:00»; подсказка «Новое время пересекается с … — в статистике осталось прежнее» |

- **F9.4 Плашка суммы.** Основная цифра — арифметическая сумма **всех** видимых строк блокнота, как на калькуляторе. Если сумма по связанным записям (их фактическое время в базе) отличается, рядом показывается вторая цифра: «В блокноте: 7 ч 00 мин · в статистике: 4 ч 00 мин». Если суммы совпадают, вторая цифра не показывается.

- **F9.5 Правка (✎) строки в блокноте** всегда меняет строку блокнота.
  - **Строка связана:** пытаемся применить то же изменение к записи в базе (обычная валидация, пересечения — без учёта самой записи). Удалось — статус «в статистике». Пересекается — запись в базе **не меняется**, статус становится «в статистике другое время».
  - **Строка не связана:** если новое время ни с чем в базе не пересекается — создаётся запись и строка связывается. Это прямое следствие правила F9.2 «без пересечений — пишем». Если пересекается — строка остаётся «не в статистике».
  - Кнопки «Записать в статистику» **нет** (решение пользователя).

- **F9.6 Правка записи в «Журнале»** всегда переносится в связанную строку блокнота (дата, время, комментарий). Это верно, даже если строка была в статусе «в статистике другое время»: последняя правка пользователя — в «Журнале». После этого статус — «в статистике».

- **F9.7 Удаление в «Журнале»** — как было (F8.12): связанная строка исчезает из блокнота и из архива, отмена в «Журнале» её возвращает. Несвязанные строки с таким же временем это **не затрагивает**.

- **F9.8 Кнопка ✕ в блокноте** — как было (F8.11): убирает строку только из блокнота, связанная запись остаётся в базе. Отмена работает. После ✕ ту же строку можно ввести снова — она станет «не в статистике», потому что время уже учтено. **Это и есть исправление исходной проблемы.**

- **F9.9 Очистка, архив, отмена, перезапуск** работают как раньше (F8.14–F8.18). Архив показывает статусы строк и обе суммы по тем же правилам, что F9.3–F9.4. Очистка, архив и ✕ **никогда** не меняют `entries` и статистику.

- **F9.10 Вкладка «Журнал» не меняется:** там по-прежнему ошибка при пересечении.

**Что заменено:**
- F8.3 (ошибка при пересечении в блокноте) → F9.2;
- F8.6 (сумма) → F9.4;
- F8.10 (правка) → F9.5–F9.6;
- в F8.16 «живой» архив теперь означает, что связанные строки получают правки из «Журнала» (F9.6).

В `docs/FEATURES.md` пометь эти строки как «изменено в v1.2.0 → F9.x», **не удаляя их**: это история.

## 3. Модель данных (новая миграция — следующий номер)

В SQLite нельзя поменять первичный ключ через `ALTER`, поэтому `notepad_items` пересоздаётся как `notepad_lines` (создать → скопировать → удалить старую → индексы), всё в одной транзакции миграции.

```sql
CREATE TABLE notepad_lines (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    sheet_id    INTEGER NOT NULL REFERENCES notepad_sheets(id) ON DELETE CASCADE,
    work_date   TEXT    NOT NULL,                                   -- как в entries
    start_min   INTEGER NOT NULL CHECK (start_min BETWEEN 0 AND 1439),
    end_min     INTEGER NOT NULL,
    comment     TEXT    NOT NULL DEFAULT '' CHECK (length(comment) <= 500),
    entry_id    INTEGER NULL REFERENCES entries(id) ON DELETE CASCADE, -- NULL = «не в статистике»
    added_at    TEXT    NOT NULL,                                   -- UTC
    updated_at  TEXT    NOT NULL,                                   -- UTC
    removed_at  TEXT    NULL,                                       -- убрана кнопкой ✕ (мягко, для отмены)
    CHECK (end_min > start_min AND end_min - start_min <= 1440)
);
CREATE INDEX ix_notepad_lines_sheet ON notepad_lines(sheet_id);
CREATE UNIQUE INDEX ux_notepad_lines_entry ON notepad_lines(entry_id) WHERE entry_id IS NOT NULL;
```

- **Перенос данных:** каждая строка `notepad_items` → строка `notepad_lines` с `entry_id` и значениями (`work_date`, `start_min`, `end_min`, `comment`), скопированными из связанной записи `entries`. Сохраняются `sheet_id`, `added_at`, `removed_at`; `updated_at` = `added_at`. После переноса у всех строк статус «в статистике». Архив не меняется.
- **Видимость строки:** `removed_at IS NULL AND (entry_id IS NULL OR entries.deleted_at IS NULL)`.
- **Физическая очистка** через 30 дней работает как раньше: каскад с `entries` и `notepad_sheets` плюс удаление строк с `removed_at` старше 30 дней.
- **Инвариант:** одна запись `entries` связана максимум с одной строкой блокнота.
