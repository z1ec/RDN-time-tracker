## 1. Правила автономной работы (прочитай первым делом)

1. **Не задавай вопросов.** При любой неоднозначности выбирай самый простой и надёжный вариант, который сохраняет данные пользователя. Решение записывай в ADR (`docs/adr/`) и в журнал (`docs/DEVELOPMENT_LOG.md`).
2. **Остановиться можно только при внешней блокировке**: `gh` не авторизован, нет прав на push, нет сети, закончились лимиты. Тогда запиши в `docs/PROGRESS.md` точное описание проблемы и что должен сделать человек, и сообщи это в ответе.
3. **Устойчивость к перезапуску.** Сессия может прерваться или контекст может сжаться. Поэтому:
   - веди `docs/PROGRESS.md` — чек-лист этапов (§11) со статусами;
   - перед началом каждого этапа и после любого перезапуска сначала читай `CLAUDE.md`, `docs/PROGRESS.md` и последние записи `docs/DEVELOPMENT_LOG.md`, затем продолжай с первого незакрытого пункта;
   - если контекст подходит к пределу — сначала обнови PROGRESS и DEVELOPMENT_LOG, потом продолжай.
4. **Каждый этап закрывается так:** сборка без предупреждений → все тесты зелёные → `dotnet format --verify-no-changes` проходит → документация обновлена → коммит → `git push` → CI на GitHub зелёный (проверяй через `gh run watch` / `gh run view --log-failed`, чини, пока не позеленеет).
5. **Доказательства вместо утверждений.** В журнал записывай реальные результаты: число тестов, номер и статус CI-запуска, хэши коммитов.
6. **Безопасность:** не используй `sudo`; не меняй глобальные настройки системы и глобальный `git config`; не трогай ничего за пределами папки проекта (кроме установки .NET SDK в `~/.dotnet`, см. §11, этап 0); не делай `force push` и не переписывай историю `main`.
7. **Визуальная проверка UI** — только через headless-скриншоты (§8.3), которые ты сам открываешь и рассматриваешь. Не оставляй GUI-процессы запущенными в фоне.
8. **Субагенты** используй для независимого ревью (этап 8) и для объёмных исследований, чтобы не засорять основной контекст.

## 3. Функциональные требования

Приоритеты: **P0** — обязательно для v1.0.0; **P1** — должно быть в v1.0.0; **P2** — желательно, а если не успеваешь — перенеси в `docs/ROADMAP.md` с обоснованием.
У каждого требования есть ID — используй их в коммитах, тестах и в `docs/FEATURES.md` (матрица «требование → код → тесты»).

### F1. Быстрый текстовый ввод периода (P0)

Однострочное поле на главном экране. При запуске приложения фокус стоит в нём; `Enter` — добавить запись.

**F1.1 Грамматика строки:**
```
[дата] <начало> <разделитель> <конец> [комментарий]
```
- **Время** (начало и конец), допустимые формы:
  - `HHmm` — `0930`
  - `Hmm` — `930`
  - `H` / `HH` — `9` → 09:00
  - `H:mm` / `HH:mm` — `9:30`, `09:30`
  - `сейчас` или `now` — текущее время с точностью до минуты (P1)
  - формат с точкой (`09.30`) **не поддерживается**: точка зарезервирована для даты, так снимается неоднозначность.
- **Разделитель** между началом и концом: один или несколько пробелов, `-`, `–`, `—` (вокруг дефиса тоже могут быть пробелы).
- **Дата** (необязательная, только первым токеном): `dd.MM` или `dd.MM.yyyy`. Без даты берётся дата, выбранная в интерфейсе (по умолчанию «сегодня»). Если у `dd.MM` текущий год даёт дату в будущем, берётся прошлый год (в январе ввод `28.12` означает прошлый декабрь).
- **Комментарий** — весь остаток строки после времени окончания, с обрезанными пробелами по краям. Если остаток **начинается** с токена, похожего на время (например, `0900 1300 1400 1800`), выдай ошибку «Похоже на второй интервал — вводите каждый интервал с новой строки».
- **Конец раньше начала** — ночная смена: конец приходится на следующий день, запись относится к дате начала (`2200 0200` = 4 ч).
- `2400` (или `24:00`) допустимо **только** как время окончания и означает конец суток.
- Длительность должна быть больше 0 и не больше 24 ч.
- Даты в будущем запрещены (запись — это факт, а не план).

**F1.2 Многострочная вставка.** При вставке нескольких строк каждая непустая строка — отдельная запись. Добавление атомарное: если хотя бы одна строка невалидна, не добавляется ничего, а ошибки показываются построчно («Строка 3: …»).

**F1.3 Живой предпросмотр** под полем при наборе: `✓ 10 нояб. · 09:00 → 18:00 · 9 ч 00 мин · «созвон»` или понятная ошибка красным с указанием проблемного фрагмента. Кнопка «Добавить» и `Enter` недоступны, пока ввод невалиден.

**F1.4 Таблица эталонных примеров.** Каждая строка таблицы обязана стать юнит-тестом. Дополни её своими пограничными случаями: всего не меньше 40 кейсов.

«Сегодня» в тестах — 10.11.2026, выбранная дата — сегодня.

| Ввод | Ожидаемый результат |
|---|---|
| `0900 1800` | 10.11, 09:00–18:00, 9 ч 00 мин |
| `900 1800` | 09:00–18:00 |
| `9 18` | 09:00–18:00 |
| `09:00 18:30` | 09:00–18:30, 9 ч 30 мин |
| `9:05-13:40` | 09:05–13:40 |
| `0900 - 1800` | 09:00–18:00 |
| `0900—1800` | 09:00–18:00 |
| `   0900    1800   ` | 09:00–18:00 |
| `0900 1800 созвон с клиентом` | комментарий «созвон с клиентом» |
| `2200 0200` | 10.11 22:00 → 11.11 02:00, 4 ч, дата записи 10.11 |
| `0000 2400` | 00:00–24:00, 24 ч |
| `15.03 0900 1800 отчёт` | 15.03.2026, комментарий «отчёт» |
| `28.12 1000 1200` | 28.12.2025 (в 2026 году эта дата ещё в будущем) |
| `15.03.2025 0900 1800` | 15.03.2025 |
| `0900 сейчас` | 09:00 – текущее время (при FakeTimeProvider = 14:37 → 14:37) |
| `1800 1800` | ❌ «Нулевая длительность» |
| `2500 1800` | ❌ «Часы должны быть от 0 до 23» |
| `0960 1800` | ❌ «Минуты должны быть от 0 до 59» |
| `2400 0100` | ❌ «24:00 допустимо только как время окончания» |
| `0900` | ❌ «Не указано время окончания» |
| `abc` | ❌ «Не удалось распознать время начала» |
| `12345 1800` | ❌ «Неверный формат времени: 12345» |
| `0900 1300 1400 1800` | ❌ «Похоже на второй интервал…» |
| `31.02 0900 1000` | ❌ «Несуществующая дата» |
| `11.11.2026 0900 1000` | ❌ «Дата в будущем» |
| пустая строка / только пробелы | игнорируется, без ошибки |

### F2. Ввод периода через форму (P0)

Раскрывающаяся панель «Ввести через форму» под полем быстрого ввода:
- **F2.1** Дата (`CalendarDatePicker`, по умолчанию сегодня, будущие даты недоступны).
- **F2.2** Начало и конец: `TimePicker` в 24-часовом формате (шаг 1 минута), рядом с каждым — кнопка «Сейчас».
- **F2.3** Комментарий: `TextBox`, до 500 символов, со счётчиком.
- **F2.4** Живой расчёт длительности и отметка «+1 день» для ночной смены.
- **F2.5** Кнопка «Добавить». Валидация **та же**, что в F1: один доменный сервис, никакого дублирования логики.

### F3. Статистика (P0, если не указано иное)

Отдельная страница «Статистика».

- **F3.1 Периоды:** День, Неделя (Пн–Вс), Месяц, Год, Всё время, Произвольный период (две даты). Навигация: ◀ / ▶ и кнопка «Сегодня». Подпись периода по-русски («Неделя 9–15 ноября 2026»).
- **F3.2 Показатели** (точные формулы — в `docs/STATISTICS.md`):
  - итого отработано;
  - количество записей;
  - рабочих дней (дней хотя бы с одной записью);
  - среднее за рабочий день = итого / рабочие дни;
  - среднее за календарный день = итого / дни периода (для текущего периода считаем дни только до сегодня включительно);
  - средняя длительность записи;
  - самый длинный и самый короткий рабочий день (дата + длительность);
  - среднее время начала (по первой записи дня) и среднее время окончания (по последней записи дня; ночные смены дают время больше 24:00, отображается как «02:00 +1»);
  - **норма (P1):** настраиваемая дневная норма (по умолчанию 8:00) × число рабочих дней недели в периоде (по умолчанию Пн–Пт; для текущего периода — до сегодня включительно) → переработка или недоработка;
  - **сравнение с предыдущим периодом (P1):** Δ в часах и в %. День → предыдущий день, неделя → предыдущая неделя, месяц → предыдущий месяц, год → предыдущий год, произвольный период → такой же по длине отрезок прямо перед ним, «Всё время» → без сравнения.
- **F3.3 Графики:**
  - по дням периода (для недели, месяца и произвольного периода) — столбцы, линия нормы, подсказка с точным значением;
  - по месяцам (для года и всего времени);
  - среднее по дням недели (P1);
  - тепловая карта года в стиле GitHub (P2).
- **F3.4 Сводка на главном экране:** «Сегодня: 6 ч 30 мин · Неделя: 31 ч 10 мин из 40 ч».
- **F3.5 Экспорт CSV выбранного периода (P1):** UTF-8 с BOM, разделитель `;`, переводы строк CRLF (чтобы русский Excel открыл файл без настроек). Колонки: `Дата;Начало;Конец;Через полночь;Длительность (мин);Длительность (ч);Комментарий`. Корректное экранирование кавычек и `;`.
- **F3.6** Ночная смена целиком относится к дате начала — это правило задокументируй.

### F4. Сохранение данных (P0)

- **F4.1** Каждое изменение сразу пишется в SQLite в транзакции. Кнопки «Сохранить» нет. После перезапуска все данные на месте.
- **F4.2 Где лежат данные:** `Environment.SpecialFolder.LocalApplicationData` + `\WorkTimeTracker\` (на Windows — `%LOCALAPPDATA%\WorkTimeTracker\worktime.db`). Аргумент командной строки `--data-dir <путь>` переопределяет папку (для тестов и self-test).
- **F4.3 Портативный режим (P1):** если рядом с exe лежит файл `portable.txt`, данные хранятся в `.\data\` рядом с exe.
- **F4.4 Миграции схемы:** таблица `schema_version`; миграции — упорядоченные SQL-скрипты (embedded resources), применяются при старте в транзакции. Миграции **только добавляются**, существующие никогда не редактируются. Тест: пустая БД → последняя версия; БД версии N → N+1.
- **F4.5 Автобэкап (P1):** раз в день при запуске — копия через SQLite Backup API в `backups\worktime-YYYY-MM-DD.db`, храним последние 14 копий. Кнопка «Сделать резервную копию сейчас» в настройках.
- **F4.6** `PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON;`
- **F4.7 Надёжность:** если БД не открывается — понятный диалог с путём к файлу и кнопкой «Открыть папку». Данные **никогда** не удаляются и не пересоздаются автоматически.
- **F4.8 (P2)** Размер и положение окна запоминаются.

### F5. Удаление записей (P0)

- **F5.1** Удалить запись: кнопка-иконка в строке, пункт контекстного меню, клавиша `Del`.
- **F5.2** Множественный выбор (`Ctrl`/`Shift`+клик) и удаление выбранного (P1).
- **F5.3 Отмена вместо подтверждения:** после удаления — всплывающее уведомление «Удалено записей: 3 · Отменить» на 8 секунд и `Ctrl+Z`. Реализация — мягкое удаление (`deleted_at`). Мягко удалённые записи старше 30 дней физически удаляются при запуске.

### F6. Комментарии и редактирование (P0)

- **F6.1** У каждой записи необязательный комментарий до 500 символов.
- **F6.2** В списке комментарий показывается в строке (длинный обрезается многоточием, полный — во всплывающей подсказке).
- **F6.3** Редактирование записи (двойной клик или иконка «карандаш»): диалог с датой, началом, концом и комментарием. Валидация та же, что при добавлении, включая проверку пересечений без учёта самой записи.
- **F6.4 Поиск по комментариям (P1):** `Ctrl+F`, без учёта регистра, **включая кириллицу**. Внимание: встроенные `LOWER`/`LIKE` в SQLite приводят к нижнему регистру только ASCII. Фильтруй в C# (`StringComparison.CurrentCultureIgnoreCase` с `ru-RU`) или зарегистрируй свою SQL-функцию. Покрой тестом «Созвон» ↔ «созвон».

### F7. Общие правила и UX

- **F7.1 Пересечения запрещены (P0):** новая или отредактированная запись не может пересекаться с существующими. Проверка идёт в абсолютных минутах с учётом соседних дней (ночная смена 10.11 22:00–02:00 пересекается с записью 11.11 01:00–03:00). Касание (`конец == начало`) допустимо. Ошибка вида: «Пересекается с записью 10.11 13:00–15:00 «обед»».
- **F7.2 Главный экран «Журнал»:** быстрый ввод → панель формы → сводка (F3.4) → список записей, сгруппированный по дням. Заголовок группы: «Пн, 9 ноября · 8 ч 15 мин». Строка: «09:00 – 13:00 · 4 ч 00 мин · комментарий · [✎] [🗑]». По умолчанию показываются последние 30 дней и кнопка «Показать ещё».
- **F7.3 Навигация:** боковая панель (`SplitView`, компактный режим): Журнал, Статистика, Настройки, О программе.
- **F7.4 Настройки:** дневная норма, рабочие дни недели, тема (Системная / Светлая / Тёмная), папка данных (показать и открыть), резервная копия сейчас, экспорт всех данных в CSV.
- **F7.5 «О программе»:** версия (из сборки), ссылка на репозиторий, путь к данным, лицензия.
- **F7.6 Горячие клавиши:** `Enter` — добавить; `Ctrl+Z` — отменить удаление; `Del` — удалить; `Ctrl+F` — поиск; `Ctrl+1…4` — разделы; `Esc` — закрыть диалог или очистить поле.
- **F7.7 Форматы:** длительность — «8 ч 05 мин»; в крупных KPI можно «8:05»; даты — по-русски через `CultureInfo("ru-RU")` **независимо от локали ОС**; время всегда 24-часовое.
- **F7.8 Тема:** по умолчанию следует системной; светлая и тёмная обе выглядят аккуратно.
- **F7.9** Иконка приложения (exe + окно), см. §8.4.
- **F7.10 Глобальная обработка ошибок:** необработанные исключения пишутся в лог (`logs\app-YYYYMMDD.log` в папке данных), пользователь видит дружелюбный диалог, данные не теряются.
- **F7.11 Режимы командной строки:**
  - `--version` — печатает версию;
  - `--data-dir <путь>` — переопределяет папку данных;
  - `--self-test` — **без запуска UI**: создаёт БД в папке данных, применяет миграции, добавляет, читает, редактирует, мягко удаляет и восстанавливает запись, считает статистику, делает бэкап, пишет отчёт в `self-test.log` в папке данных и завершается с кодом 0 (успех) или 1 (ошибка). Этим режимом CI проверяет настоящий Windows-exe (в том числе то, что нативный SQLite корректно упакован в single-file).

## 4. Модель данных

Время хранится как **локальное «настенное» время** в минутах от начала даты записи. Часовые пояса и переход на летнее время не учитываются (ADR-0003).

```sql
CREATE TABLE entries (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    work_date   TEXT    NOT NULL,                  -- 'yyyy-MM-dd', дата начала
    start_min   INTEGER NOT NULL CHECK (start_min BETWEEN 0 AND 1439),
    end_min     INTEGER NOT NULL,                  -- > 1440 → следующий день
    comment     TEXT    NOT NULL DEFAULT '',
    created_at  TEXT    NOT NULL,                  -- UTC, ISO-8601
    updated_at  TEXT    NOT NULL,                  -- UTC, ISO-8601
    deleted_at  TEXT    NULL,                      -- мягкое удаление
    CHECK (end_min > start_min AND end_min - start_min <= 1440),
    CHECK (length(comment) <= 500)
);
CREATE INDEX ix_entries_work_date ON entries(work_date) WHERE deleted_at IS NULL;

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE schema_version (version INTEGER NOT NULL, applied_at TEXT NOT NULL);
```

Примеры: `0900 1800` → `start_min=540, end_min=1080`; `2200 0200` → `start_min=1320, end_min=1560`; `0000 2400` → `0, 1440`.
Длительность = `end_min − start_min`.

В домене: `WorkEntry` (record: `Id`, `DateOnly Date`, `TimeOnly Start`, `int StartMinute`, `int EndMinute`, `bool EndsNextDay`, `string Comment`, `TimeSpan Duration`), value object `TimeRange`, `PeriodKind`, `Period`, `PeriodStatistics`, `ParseResult`/`ParseError`.

## 8. Сборка, CI/CD, скриншоты, иконка

### 8.1 `ci.yml` (на push в `main` и на PR)
1. **job `test`** (`ubuntu-latest`): setup-dotnet по `global.json` → `restore --locked-mode` → `dotnet format --verify-no-changes` → `build -c Release` → `test` с покрытием → проверка порога покрытия Core ≥ 90%.
2. **job `windows`** (`windows-latest`, `needs: test`): `dotnet publish` (команда ниже) → запуск **реального exe** в режиме self-test:
   ```powershell
   $dir = Join-Path $env:RUNNER_TEMP "wtt-selftest"
   $p = Start-Process -FilePath "artifacts/win-x64/WorkTimeTracker.exe" `
        -ArgumentList "--self-test","--data-dir",$dir -Wait -PassThru
   Get-Content (Join-Path $dir "self-test.log")
   if ($p.ExitCode -ne 0) { exit 1 }
   ```
   → `upload-artifact` (`WorkTimeTracker-win-x64`, сам exe).
3. `concurrency` с отменой устаревших запусков; `permissions: contents: read`.

Команда публикации (её же используют `scripts/publish-win.sh` и `release.yml`):
```bash
dotnet publish src/WorkTimeTracker.App/WorkTimeTracker.App.csproj -c Release -r win-x64 \
  --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true -p:PublishTrimmed=false -p:DebugType=none \
  -p:Version=$VERSION -o artifacts/win-x64
```
Кросс-публикация `win-x64` должна работать и локально на macOS — проверь это сам через `scripts/publish-win.sh`.
