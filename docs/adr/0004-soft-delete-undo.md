# ADR-0004: Мягкое удаление и отмена вместо подтверждения
- Статус: принято · Дата: 2026-11-09

## Контекст
Удаление — частая операция (опечатки, дубли), а диалог «Вы уверены?» раздражает и всё равно не спасает от ошибок: его прокликивают не читая. При этом данные пользователя нельзя терять (F4.7).

## Решение
- Удаление проставляет `deleted_at` (мягкое удаление). Все выборки приложения фильтруют `deleted_at IS NULL`.
- После удаления 8 секунд показывается уведомление «Удалено записей: N · Отменить»; `Ctrl+Z` тоже отменяет удаление (F5.3).
- Отменить можно **последнее** удаление, пока после него не было других изменений (добавления, редактирования, нового удаления). Так восстановление не может создать пересечение с записью, добавленной после удаления (ADR-0007). После скрытия уведомления `Ctrl+Z` продолжает работать по тому же правилу.
- При каждом запуске записи, удалённые более 30 дней назад, удаляются физически.

## Рассмотренные альтернативы
- **Диалог подтверждения** — лишний шаг на каждое удаление, не защищает от «прокликивания».
- **Физическое удаление + стек отмены в памяти** — данные теряются при падении программы между удалением и отменой; сложнее восстановить исходные Id.
- **Корзина без срока** — БД бесконечно растёт мусором.

## Последствия
- ➕ Быстрое удаление без диалогов и безопасная отмена; удалённое ещё 30 дней можно восстановить вручную из файла БД.
- ➖ Каждый запрос обязан фильтровать `deleted_at IS NULL` — это инвариант, записанный в CLAUDE.md и проверяемый тестами репозитория.
- ➖ Отмена только последнего действия, не полная история.
